Documentatie en ontwikkeling

Broncode-indeling

main.py voert de kluis-state-machine uit in vijf threads: knop, sensoren en OLED, actuatoren, cloud en spraak. Ondersteunende modules: vault_state.py (configuratie en gedeelde status), sensors.py (potentiometer, LM35, BH1750), display.py (OLED-schermen), zwaailicht.py (RGB-led en rood/uit-waarschuwingsknipperlicht), vault_lock.py (relais en stepper), mqtt_client.py (ThingSpeak-telemetrie en lokale perimeter-subscriber) en notificaties.py (ntfy-push en sirene). voice.py voert Vosk-spraakherkenning uit voor de tweede factor (standaard model-en/; model-nl/ is beschikbaar). Bekijk de pagina Code voor de volledige uitleg.

De site aanpassen en lokaal bekijken

De site bestaat uit gewone HTML- en CSS-bestanden in docs/; er is geen thema, generator of package-installatie nodig. Gebruik relatieve links zodat de site werkt op de GitHub Pages-URL van de repository.

Voer deze opdrachten uit vanuit de repositoryroot:

python -m unittest discover -s tests -p "test_documentation.py"
python -m http.server 8000 --bind 127.0.0.1 --directory docs

Open http://127.0.0.1:8000 om de site te bekijken. Stop de server met Ctrl+C. De controles testen paginametadata, lokale links, fragmenten en verwijzingen naar afbeeldingen en CSS zonder GPIO te gebruiken of met ThingSpeak te verbinden.

Publiceren met GitHub Actions

  1. Open in de repository-instellingen Pages en stel bij Build and deployment / Source GitHub Actions in. Een repositorybeheerder hoeft dit maar één keer te doen.
  2. Open een pull request naar master. De workflow Documentation controleert de site en maakt een Pages-artifact; deze publiceert de pull request niet en maakt geen gehoste preview.
  3. Een merge naar of push naar master voert dezelfde controles uit en publiceert het artifact naar de omgeving github-pages.

Kies niet voor Deploy from a branch: die optie start ook GitHubs automatisch gegenereerde workflow voor Pages-build en deployment, waarvan de actieversies niet door deze repository worden beheerd. Laat GitHub Actions geselecteerd zodat .github/workflows/pages.yml de enige publisher is en de Node.js-runtimes hier bijgewerkt kunnen worden.

Na de eerste geslaagde deployment hoort de site beschikbaar te zijn op wouterheijligen.github.io/IoT_SmartVault/. De deploymentjob rapporteert de daadwerkelijke URL. Handmatig starten kan ook via Actions; alleen een run op master kan publiceren.

Pull requests hebben alleen-lezen repositoryrechten. Alleen de deploymentjob vraagt Pages-schrijfrechten en een identity token aan. Als de omgeving github-pages branchbeperkingen heeft, moet master worden toegestaan; ingestelde goedkeuringsregels blijven gelden.
